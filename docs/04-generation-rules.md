# 04. 生成ルールと出力テンプレート

実装：`src/domain/selection.ts`（場面選択・不足質問・影響判定）、`src/domain/scenes.ts`（カタログ）、`src/ai/claude.ts`（AI生成）、`src/domain/demoGenerator.ts`（DEMO）、`src/domain/quality.ts`（検証）。

## 1. 場面の選択ルール

| ルール | 内容 |
|---|---|
| R1 フロー固有 | S01・S07 は①のみ、S02・S08 は②のみ。他方のフローでは「対象外（理由付き）」。 |
| R2 目的依存 | S13（商談打診）は目的に「商談」、S14（資料送付）は「資料送付」を含む場合のみ。目的未入力なら暫定的に生成し「要確認」を付ける。 |
| R3 R分類は台本化しない | 鳴りっぱなし・留守電・音声ガイダンス系・電源OFF・使われていない・電話番号調査は場面を持たない。結果状態（商談OK等）は、**そこへ至る打診と成立後の確認**の場面（S13/S14）に対応づける。 |
| R4 尊重すべき結果 | 次回コール不可（会社要因／担当要因・クレーム）、会社方針の拒否、本人確認後の拒否、メール転送NG は `noRecontact` ケース。再連絡・再勧誘を示唆する語を品質チェックで検出する。 |
| R5 ①→②の移行 | 「キーマン名入手（16）」、および注記75（商談OK／資料送付OKの直下）を移行条件として表示（いずれも要確認）。②内では「後任者入手（119）→後任者へ取次依頼・②として再コール」。 |
| R6 条件で文面を変える | ②の S02 は接点の強弱で2ケース。S02/S03/S11 はリスト来歴・接点の強さ・接点の経緯を入力スナップショットに含め、変更時に再生成候補にする。 |

## 2. 不足情報の質問ルール

1. 選択された場面の `requiredInputs ∪ optionalInputs` を集計。
2. 回答済み・「不明」・「現時点では省略」の項目は質問しない。
3. 優先度 = 項目の重要度（1〜5）＋（どの場面でも必須でなければ +3）。同順位は影響場面数の多い順。
4. 一度に **5件** まで提示。各質問に「目的／十分な回答の基準／不足時の追加質問／矛盾確認／影響場面」を付ける。
5. 矛盾（例：来歴＝新規なのに接点＝強い）は確定せず確認を促す。

## 3. 生成（1場面＝1回のAI呼び出し）

- 入力：フロー説明、案件の回答（`intake:キー`）、資料（`<source_document id="doc:…">` に格納し、中の命令には従わない）、関連ナレッジ（`kn:ID` と status）、場面仕様（目的・話し相手・条件・避ける表現・ケースと元図形・ガードレール）。
- 出力スキーマ（structured outputs、Zodで型検証）：

```json
{
  "scene_id": "S09",
  "cases": [
    { "case_id": "wary", "intent": "…", "short": "…", "standard": "…", "supplement": "" }
  ],
  "avoid": ["…"],
  "evidence_refs": ["intake:productName", "doc:…", "kn:…"],
  "uncertainties": ["…"]
}
```

- 構造検証：scene_id 不一致／未定義 case_id／ケース欠落・重複／本文欠落 → エラー内容を添えて **1回だけ再生成**。存在しない出典参照は除去して「要確認」に記録。
- 保存形式（`ScriptScene`）：`scene_id, title, applicability_conditions, purpose, cases[{case_id,label,condition,intent,variants[{style: short|standard|supplement, text}]}], avoid, evidence_refs, uncertainties, review_status, generated_by, input_snapshot, quality_warnings`。
- `review_status`：AI生成＝`AI_PROPOSAL`、テンプレート＝`DEMO`、人が承認＝`CONFIRMED`、承認後に変更＝`NEEDS_CONFIRMATION`。

## 4. 文面の約束事

- 架電時に差し込む値は変数で書く：〔オペレーター名〕〔キーマン氏名〕〔先方社名〕〔在席日時〕〔検討時期〕〔後任者氏名〕〔入手したキーマン氏名〕〔メールアドレス〕。人名・社名は創作しない。
- 未入力の事実は【要確認：項目名】と書き、uncertainties に記録する。
- ①では〔キーマン氏名〕を使わない。②の指名取次（S02）では必ず使う。
- 本人宛の場面（S03・S11〜S17）に受付向けの取次ぎ文言を入れない。
- short は1〜2文、standard は2〜4文。1行90字を超えたら警告。

## 5. 品質チェック（`qualityWarnings`）

①で〔キーマン氏名〕使用／②S02で未使用／本人宛に取次文言／`noRecontact` ケースに再連絡語（改めて・またご連絡・後日 等）／押し付け表現（せめて・少しだけでも 等）／**資料・回答にない数値（%・社・件・円 等）**／NG表現／長すぎる行／【要確認】の残存。

## 6. 修正（自然言語）

1. 対象場面を選び、指示を入力 → AIは `changes[{scene_id, case_id, style, new_text, reason}]` と `impact_notes` を返す。
2. 対象外の場面・存在しない case/style への変更はサーバー側で破棄。
3. 差分（文字単位）と理由を表示。**人が採用した変更だけ**で新しい版を作る。他の場面はバイト単位で不変（テストT24）。
4. 手編集・承認状態の変更・元に戻すも、すべて新しい版として履歴に残る。
5. APIキー未設定時は「短く」「丁寧に／弱めに」のみ規則ベースで処理（依頼文・変数は削らない）。

## 7. 出力

- Markdown（版指定可）：場面ごとの短い版／標準版／補足、承認状態、使用条件、避ける表現、要確認、**台本化しない結果の一覧**。
- 画面：場面単位・バリエーション単位のコピー、印刷（完成版タブのみ印刷される）。
